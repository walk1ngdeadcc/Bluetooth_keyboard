# 按键模块

> 说明：当前工程中的实际矩阵按键实现已经切换为官方 `CAF buttons`。
> 本文里的 GPIO 分配和稀疏矩阵参考仍然有效，但扫描实现细节请以 [按键唤醒.md](</D:/code/SGGProject/Bluetooth_keyboard/docs/按键唤醒.md:1>) 和当前代码为准。

## 1. 模块目标

当前按键模块先完成下面两件事：

- 基于 `4 列 x 6 行` 的矩阵键盘完成扫描
- 按下或释放按键时，通过 RTT 打印对应的 `row/col`

本版没有接入蓝牙 HID 键值映射，只做矩阵扫描和调试验证。

## 3. 软件实现

### 3.1 驱动选型

当前实现使用独立的应用层扫描模块，矩阵引脚参数仍然放在设备树里：

- 已在实板测通
- 模块独立，便于后续继续接 HID
- 当前阶段比再切回通用驱动更稳

### 3.2 文件位置

- 设备树矩阵定义：`app.overlay`
- 按键模块实现：`src/key_matrix.c`
- 按键模块头文件：`src/key_matrix.h`

### 3.3 扫描方式

根据实板 RTT 诊断结果，当前固定使用下面这套方式：

- 列线输出有效高电平
- 行线输入下拉
- 逐列扫描

也就是：

- `col` 被依次拉高
- `row` 读取高电平表示按下

### 3.4 事件输出

按键状态变化时，会通过 RTT 输出：

```text
matrix key down: row=1 col=2
matrix key up: row=1 col=2
```

## 4. 图片对应的有效键位

根据你给的图片，原本计划按“稀疏矩阵”处理。

原始规划的有效位如下，保留在这里作为后续参考：

| Row\Col | C0 | C1 | C2 | C3 |
| --- | --- | --- | --- | --- |
| R0 | Y | N | N | N |
| R1 | Y | Y | Y | Y |
| R2 | Y | Y | Y | N |
| R3 | Y | Y | Y | Y |
| R4 | Y | Y | Y | N |
| R5 | N | Y | Y | Y |

对应原始 `actual-key-mask`：

```dts
actual-key-mask = <0x1f 0x3e 0x3e 0x2a>;
```

按列解释：

- `0x1f`：C0 上存在 `R0~R4`
- `0x3e`：C1 上存在 `R1~R5`
- `0x3e`：C2 上存在 `R1~R5`
- `0x2a`：C3 上存在 `R1/R3/R5`

当前代码还没有重新启用这个稀疏掩码，目的是先把基础扫描跑稳定。等你把所有实物键位确认一遍后，再把这个掩码加回去。

## 5. 当前结论

实板已经证明下面两种诊断模式会响应：

- `normal_high`
- `swapped_low`

这说明硬件至少已经导通，且按你现在的 `row/col` 命名，最终应锁定为：

- `normal_high`

也就是：

- `col` 作为扫描输出
- `row` 作为输入采样
- `col` 有效态为高
- `row` 采用下拉

## 6. 验证方法

烧录后连接 RTT Viewer，正常启动会看到：

```text
key matrix ready: rows=6 cols=4
scan mode: cols active high, rows pull-down
RTT test: press any key to print row/col
keyboard app ready
matrix scanner started: cols active high, rows pull-down
```

按下任意一个物理按键时，应该看到类似：

```text
matrix key down: row=x col=y
matrix key up: row=x col=y
```

## 7. 下一步建议

按键模块稳定后，建议按下面顺序继续：

1. 确认所有物理键位对应的 `row/col`
2. 加回稀疏矩阵掩码
3. 增加 `row/col -> 键值` 映射
4. 接入蓝牙 HID Keyboard
5. 再叠加 RGB 灯和唤醒策略

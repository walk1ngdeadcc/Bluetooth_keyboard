# 蓝牙模块说明

## 目标

本项目在现有 `USB HID` 键盘链路基础上，增加 `BLE HID` 模块，实现以下能力：

1. 模式切到 `BLE` 时禁用 `USB`，模式切到 `USB` 时禁用 `BLE`
2. 首次进入蓝牙模式时主动广播配对信息，让电脑弹出配对入口
3. 已配对设备下次自动回连
4. 蓝牙 HID 同时支持：
   - 数字键盘
   - 音量旋钮

## 使用的官方模块

蓝牙实现没有重造轮子，直接复用了 NCS/Zephyr 官方能力：

- `bt_hids`
  - Nordic 官方 HID over GATT 服务
  - 文件来源：`nrf/include/bluetooth/services/hids.h`
- `bt_le_adv_prov` + `swift_pair`
  - Nordic 官方广告 provider
  - 用于 Windows Swift Pair 弹窗
- `settings` + `BT_SETTINGS`
  - 用于保存 bond 信息
  - 下次上电后自动识别已配对设备
- `BT_FILTER_ACCEPT_LIST`
  - 用 accept list 只允许已绑定设备重连

## 模块结构

### 1. `src/ble_hid_module.c`

负责蓝牙 HID 主体：

- 初始化蓝牙协议栈
- 初始化 `bt_hids`
- 启动配对广播或回连广播
- 处理连接、断开、加密状态变化
- 发送键盘输入报告
- 发送 consumer control 报告

当前 HID 内容：

- 键盘报告：
  - 数字键盘按键
  - NumLock
  - 小键盘 Enter
  - 小键盘 Dot
- Consumer 报告：
  - 音量加
  - 音量减
  - 静音

### 2. `src/transport_manager.c`

负责传输层互斥控制：

- `APP_MODE_USB`
  - 关闭 BLE
  - 开启 USB
- `APP_MODE_BLE`
  - 关闭 USB
  - 开启 BLE
- `APP_MODE_24G`
  - 关闭 USB
  - 关闭 BLE

切换模式时会先释放 HID 按键状态，避免卡键。

### 3. `src/mode_switch.c`

负责读取 ADC 模式拨杆并发出模式事件：

- `USB`
- `2.4G`
- `BLE`

模式变化后通过 `mode_changed_event` 通知 `transport_manager`。

### 4. `src/usb_hid_module.c`

原有 USB HID 模块已补充开关控制：

- `usb_hid_module_set_enabled(bool enabled)`
- `usb_hid_module_release_all()`

同时修复了一个重要问题：

- 以前即便切到 BLE，只要 USB VBUS 变化，USB 仍可能被重新拉起
- 现在会受 `usb_enabled` 状态约束，不会破坏 USB/BLE 互斥

### 5. `src/mode_event.*`

新增统一模式事件：

- `APP_MODE_USB`
- `APP_MODE_24G`
- `APP_MODE_BLE`

## 配对与自动回连逻辑

### 首次配对

当进入 `BLE` 模式且当前没有 bond 时：

- 启动普通可连接广播
- 打开 `Swift Pair` provider
- 电脑端应能看到蓝牙配对弹窗或在蓝牙设备列表中快速发现设备

### 已配对后的行为

当设备已有 bond 时：

- 启动 accept list 广播
- 只允许已绑定设备连接/扫描响应
- 电脑下次打开蓝牙或设备切到 BLE 模式时会自动回连

### 存储

bond 信息通过以下能力持久化：

- `CONFIG_BT_SETTINGS=y`
- `CONFIG_SETTINGS=y`
- `CONFIG_SETTINGS_NVS=y`
- `storage_partition`

板级 DTS 已有：

- `boards/cc/Bluetooth_keyboard/Bluetooth_keyboard.dts`
- `storage_partition: partition@f8000`

## HID 输入来源

蓝牙模块不直接读硬件，仍复用现有输入链路：

- `src/key_matrix.c`
  - 产生数字键盘 `button_event`
- `src/rotary.c`
  - 产生音量加减 `button_event`
- `src/keymap.c`
  - 把 `key_id` 映射为：
    - keyboard usage
    - consumer usage

这样 USB 和 BLE 使用的是同一份输入事件，不需要改矩阵和旋钮驱动。

## 关键配置

主要配置在 `prj.conf`：

- `CONFIG_BT=y`
- `CONFIG_BT_PERIPHERAL=y`
- `CONFIG_BT_SMP=y`
- `CONFIG_BT_HIDS=y`
- `CONFIG_BT_ADV_PROV=y`
- `CONFIG_BT_ADV_PROV_SWIFT_PAIR=y`
- `CONFIG_BT_SETTINGS=y`
- `CONFIG_BT_FILTER_ACCEPT_LIST=y`
- `CONFIG_BT_MAX_CONN=1`
- `CONFIG_BT_MAX_PAIRED=1`

说明：

- `MAX_CONN=1`
  - 当前设计只允许一个蓝牙主机连接
- `MAX_PAIRED=1`
  - 当前设计只保留一个已配对主机
- `FILTER_ACCEPT_LIST`
  - 是自动回连链路的关键配置

## 初始化顺序

`src/main.c` 当前建议顺序：

1. `app_event_manager_init()`
2. `rotary_init()`
3. `power_module_init()`
4. `usb_hid_module_init()`
5. `ble_hid_module_init()`
6. `transport_manager_init()`
7. `mode_switch_init()`
8. `key_matrix_init()`

这样能保证模式事件发出前，USB/BLE 传输层已经可被控制。
